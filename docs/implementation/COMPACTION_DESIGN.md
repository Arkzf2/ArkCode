# ArkCode 首版上下文压缩设计

状态：已接入运行时，作为首版实现规范维护。更新日期：2026-10-29。

本文定义 ArkCode 自有 compact。Pi 继续提供模型调用和会话基础能力，原生摘要生成、历史保留和压缩触发不再拥有策略。历史查询工具、历史 window 提示和后台压缩留待后续。

## 首版必须成立的条件

- 保留最近最多 20,000 token 预算的真实用户文本，排除媒体、生成摘要和环境注入。
- 在下一次模型请求前检查完整输入，在工具调用已闭合的安全点执行。
- 新 query 在快照截止点之后只出现一次，loop 压缩后继续未完成任务。
- 只有有效、完整且能满足请求预算的摘要才允许提交。
- 重试裁剪只影响摘要请求副本，不改写 JSONL 中的原始历史条目。
- 新摘要、当前上下文基线和工具配置使用同一检查点，提交前失败不发布新状态。
- 重启、resume 和 fork 与运行时使用相同的检查点投影。

## 用户原文的识别与保留

在 CLI 或 SDK 接收任务输入时保存 inputId、rawText、origin、delivery 和关联消息 ID。rawText 在 skill 展开和附件处理之前捕获。origin 区分 human、harness、summary 和 context。delivery 区分 prompt、steering、follow-up 和任务命令。/compact、/model、/tool-mode 等控制命令不是对话 query。

20k 是估算 token 预算，不是字符数。有适配模型的 tokenizer 时使用该 tokenizer。否则文本采用 Codex 的近似规则 ceil(UTF8 字节数 / 4)，并标记 estimate，不声称精确 token 数。选择、截断、摘要预算和请求文本计量共用该文本计量入口。保留用户亲自输入的文本、代码、日志和任务命令。排除自动展开的 skill 正文、附件正文、媒体、环境消息和摘要。

当前实现统一使用 UTF-8 字节估算，尚未接入模型专用 tokenizer。图片按 SDK 原有的每张 1200 token 启发式计量，不能视为供应商实际图像开销的上界。实际 overflow 会覆盖估算结果，进入单次恢复或暂停流程。

候选集合为上一检查点保留的用户原文范围，加本次截止点之前新增的真实用户文本。首次压缩读取当前有效分支。后续不复活已撤回、其他分支或上次已经省略的用户输入。rawText 与范围引用负责避免把生成的截断标记再次当作原文。

从最新消息向前消耗预算。完整放得下的消息保留原文。边界消息保留首尾，扣除省略标记预算后将剩余文本预算均分给首尾，然后停止向前选择。恢复时间顺序。ArkCode 将省略标记也计入 20k，区别于 Codex 字符截断器把标记放在保留文本预算之外。标记放不下时缩短标记和片段，不生成超预算文本，不切断 Unicode 码点。

媒体与文本混合消息仅保留人工文本。媒体专属消息不生成空 user 占位，相关任务状态由摘要交接。只有存在符合条件的用户文本时，才有“最后一条保留用户输入”。已完成任务仍可保留原文。

新提交但尚未交给模型的 query 放在快照截止点之后。该 query 完整保留，不消耗本次 20k 历史预算，但计入触发及最终请求校验。输入本身过大时明确报错，不作为历史边界消息静默截断。

## 触发、预算与压缩后目标

每次模型请求准备完成后计量，包括工具循环续接和模型切换。自动压缩只在没有流式响应、没有等待结果的模型工具调用时运行。后台进程可以继续存在，其状态需单独交接。压力判断不能只读取上次 assistant usage。追加的工具结果、环境和新 query 都要计入。

预算定义如下。O 是实际请求的输出预留，不是模型宣传的最大输出上限。若供应商独立定义输入容量，适配器按协议计算 B，避免重复扣除 O。

~~~text
W = 有效模型总窗口
O = 本次正常请求实际输出预留
B = min(供应商独立输入上限, W - O)，共享窗口模型适用
I = 完整请求输入估算，含 system、tools、媒体、消息包装和待发送输入
R = W >= 200_000 ? 50_000 : 25_000
T = floor(min(0.90 * B, B - R))

自动触发：I >= T
安装条件：I_after < T 且 I_after < I_before
硬限制：正常请求和摘要请求分别满足其输入与输出容量约束
~~~

采用前面约定的“有效输入容量”口径，90% 与额外输入余量使用同一个 B。模型总窗口 W 小于 200K 时额外预留 25K，大于等于 200K 时额外预留 50K；分档依据不是扣除输出后的 B。这是输出预留之外的 ArkCode 输入余量策略。所有预算包含生成标记、摘要前缀和当前上下文。使用安装后的工具配置重新检查 I_after。

90% 比例和 20K 用户原文保留预算不随分档改变。若 T 不为正，或固定上下文、待发送输入和应保留原文已使目标无法达到，返回 budget-insufficient，保留旧状态，并显示当前分档的输入余量。诊断区分规则与工具开销、用户原文、待发送输入和摘要，不建议反复重试同一快照。

模型容量或实际输出配置缺失时，不凭模型名称猜窗口。要求适配器或显式模型配置提供容量后再压缩。媒体只经当前模型适配器支持的方式发送给摘要模型，不将无法理解的媒体静默改写成事实。媒体不兼容或其开销无法安全容纳时明确失败，首版不增加自动媒体外置。

当前 ArkCode 没有独立的每请求输出设置，正常请求从模型配置的 maxTokens 出发。预算保守预留该上限；对于 OpenAI 兼容协议，还计入 samplingParams 及各思考级别中显式配置的输出上限，取最大值。供应商适配器按剩余窗口调低输出不会反向放宽 ArkCode 策略。摘要调用显式收紧这些继承的输出字段。首版统一按共享总窗口计算，尚无独立输入容量适配器。

摘要没有另设一个缺少依据的固定 8k 上限。沿用当前模型实际输出配置，并收紧到候选检查点可容纳的摘要预算。摘要前缀和消息包装先扣除。摘要请求仍要为该输出预算留出容量。可用摘要预算不为正时直接失败。

首次计量是估算，不能称为已证明的容量上界。供应商返回 usage 后用于下一次请求校准，并为尚未计入 usage 的新消息补估。上下文容量包含缓存命中的输入，不能只用未缓存输入 token 判断压力。旧窗口的 usage 不能作为新窗口已用量。无新增历史时不重复自动压缩。同一快照、同一模型与配置已失败时，阻止无进展循环，允许显式重试或在输入、模型、配置变化后重试。

## 压缩请求与交接提示

普通 local 模型请求负责生成摘要，沿用当前选择的 provider、model 和有效系统规则。首版不自动切换供应商或使用 remote compact。请求仍通过已配置的模型适配器，保留历史的工具调用与结果配对。摘要请求不执行工具，不将部分摘要当作正常 assistant 回答追加。

首次摘要输入为当前有效压缩上下文，其中包含上一份摘要、保留的用户文本和此后新增历史。首版不遍历原始 JSONL 恢复被压缩掉的旧消息。重试使用这个快照的临时副本。输出提示见 [压缩提示](COMPACT_PROMPT.md)。

提示沿用 Codex 的四个交接重点：当前进度与关键决策，约束与用户偏好，未完成工作和明确下一步，以及继续任务必需的数据与引用。不增加必须填写的六段或八段模板。允许按任务组织标题，避免无信息空段。

ArkCode 补充执行状态要求：区分已完成、已尝试、失败和计划执行。保留关键命令、文件路径、错误、验证结果和活跃任务标识。用户后续修正覆盖旧要求。裁剪后的记录只支持其仍可见的信息，摘要明确证据缺失。摘要不承诺历史检索。

收集完整模型响应后，要求存在非空文本、正常结束、未取消且没有待执行工具调用。拒绝输出截断、空文本和错误响应。该验证在所有压缩时机执行，强于 Codex local 在不同 phase 中的非空处理。程序无法证明摘要语义完整，依靠提示、真实协议回归和后续任务验证评估。

模型返回文本作为交接摘要，程序按 Codex 原版 SUMMARY_PREFIX + 换行 + 摘要组装，不再另写一套续接前缀。摘要生成指令与续接前缀分别维护，修改生成指令不要求同时修改前缀。持久化 origin=summary，后续保留用户信息时直接排除，不依赖前缀文本识别来源。即使协议将该消息序列化为 user role，也不改变它的来源。前缀不恢复被移出的工具消息，也不改变当前权限与工具声明。

## 大工具结果的临时裁剪

采用 DSH 的默认算法与数值，单位是 Unicode 码点，不是 token，也不是 JavaScript UTF-16 长度。

| 参数 | 首版默认值 |
| --- | ---: |
| thresholdChars | 8192 |
| headChars | 4096 |
| tailChars | 1024 |

仅当一条工具结果的所有 text 块合计超过 8192 码点时裁剪。将这些 text 块看作连续文本，保留最前 4096 和最后 1024 码点，在移除区第一次出现的位置插入下面的固定标记。

~~~text


[... tool result middle pruned ...]


~~~

标记准确值为两个换行、方括号内文本、两个换行。跨块只插入一次。保留非文本块及其相对顺序。工具名、call ID、错误状态、调用参数和其他元数据不变。只处理结果 text，不裁剪用户、assistant 文本或工具调用参数。

要求 head + marker + tail <= threshold，替换后严格更短。同一结果再次应用得到相同内容，重复重试不继续剪掉首尾。候选为本次摘要快照中全部超限工具结果，包括最新结果，不采用“保护最近 N 轮”。这使最新结果也可能损失中间证据，摘要必须据实说明。存在不等于允许执行，已结束工具不能因摘要裁剪而重跑。

与 DSH 的区别有两个。第一，ArkCode 在输入溢出后的重试使用裁剪，不在正常压力触发时先剪裁并尝试跳过摘要。第二，裁剪不写入 live history、不生成持久化替换事件。完整原始结果仍在 JSONL，首版不附带查询入口。字符裁剪不能保证 token 预算达标，每次仍需重新计量完整请求。

## 失败、重试和取消

每次压缩最多两次摘要内容尝试。每次内容尝试的可恢复网络错误最多额外重试两次，沿用 ArkCode 当前有限重试配置并退避。停止重复的嵌套 SDK 重试，统计实际请求数。下表中的“重试一次”共享第二次内容尝试，不叠加成多轮回退。

| 原因 | 行为 |
| --- | --- |
| 首次摘要输入估算已超限，或供应商返回 context overflow | 保持真实原文，临时裁剪全部超大工具结果，重新计量后尝试一次。估算已超限时不发送一个已知放不下的原请求 |
| 裁剪没有收益，或裁剪后仍超限 | 失败。不删除最旧用户消息，不删除任意历史来拼出摘要请求 |
| 网络中断、可恢复 5xx、限流 | 保持相同内容有限退避重试。遵循供应商重试提示；不可恢复鉴权与配置错误直接失败 |
| 摘要为空或输出截断 | 拒绝候选。若还有内容尝试，要求在同一预算内更简洁地完整输出，不执行无关工具裁剪 |
| 摘要使完整请求仍超目标或没有缩减 | 拒绝候选。若还有内容尝试，按剩余预算生成更短摘要 |
| 用户取消 | 终止调用，不提交、不切换工具配置、不自动再压缩 |
| 重试耗尽 | 返回失败，保持提交前历史和工具策略 |

该行为有意不同于 Codex local 的 overflow 分支：Codex 可以从摘要请求临时历史中移除最旧条目后继续。ArkCode 首版按用户约定只做工具结果裁剪，仍然放不下时明确停止。超大用户文本、工具声明或媒体引发的失败因此可能需要用户调整输入或模型。

### 重试耗尽后的会话状态

压缩失败不等于会话失效。提交前失败不安装候选摘要或临时裁剪历史，原始 JSONL、当前有效历史、待处理输入和已完成工具结果保持原状。是否继续执行取决于下一次请求的容量与失败原因，不能仅凭“压缩失败”决定继续或退出。

| 状态 | 是否继续模型执行 | 处理 |
| --- | --- | --- |
| 自动压力压缩失败，但旧历史组装的下一次正常请求仍满足硬容量约束 | 可以 | 显示警告，使用旧检查点和仍有效的工具配置继续；每次请求重新计量，不把这次放行视为永久跳过压缩 |
| 下一次正常请求已放不下，或普通请求已实际返回 overflow 且 compact 失败 | 暂停 | 保留会话与未交付输入，不再按原请求自动发送；允许查看历史、修改模型或配置及显式重试 |
| 用户明确取消压缩或当前运行 | 不自动续跑 | 按取消意图返回控制权，保留未提交前状态；后续由用户继续 |
| 摘要检查点已提交，但内存历史或工具配置未激活完成 | 阻止请求直到恢复激活 | 以持久化检查点为权威，先完成激活；不能退回旧历史继续发请求 |

压力触发阈值 T 是提前压缩的策略线，不是模型硬限制。放行时仍须计入完整旧历史、待发送输入、system、tools、媒体和本次输出预留。估算可容纳但供应商实际返回 overflow 时，以该错误为准进入暂停或单次恢复流程，不能反复把同一请求判为可发送。鉴权、配置等错误本身阻止正常模型请求时，仍按对应错误暂停，不通过压缩失败降级绕过。

恢复入口为修复可恢复错误后显式重试 compact，或调整模型与预算配置后重新校验。切换到更大窗口也必须经过模型、媒体和工具兼容检查。确定性超限时重复同样的裁剪没有收益；追加新 query 也不会释放容量。原任务和待处理输入通过既有 inputId 与交付状态恢复，不要求另开会话，不重复提交 query 或执行已完成工具。暂停仅保证不新增模型执行请求，不隐式终止既有后台进程。

同一快照、模型和配置上的自动失败需记录并抑制无进展重试；显式重试或输入、模型、配置发生变化后才重新尝试。普通模型请求已经返回 overflow 时，可以执行一次成功 compact 后重试模型请求；不重新执行历史工具。再次 overflow 则暂停，保留失败诊断。首版不自动切换供应商、不安装空或截断摘要，也不删除最旧历史作为隐藏降级。

## 请求布局和有效上下文

~~~text
[system：静态规则和本次生效的工具模式说明]
[tools：与 system 对应的当前工具声明]
[较早保留的真实用户文本]
[当前有效上下文完整基线]
[最后一条保留的真实用户文本，如果存在]
[历史交接前缀 + 新摘要]
------------ 持久化检查点 ------------
[新 query 或快照之后的其他有效输入]
[后续按需追加的上下文差量]
[新的 assistant 和 tool 消息]
~~~

保留集合为空时，当前上下文直接放在摘要之前。首版不保留近期原始 assistant 或工具尾部，不注入历史查询说明。持久化检查点不是模型消息。

当前上下文从可信程序状态重建，包括环境、项目指令和程序已管理的任务状态。工具配置决定工具模式 system 段与 tools。权限和执行资格在实际执行时检查，摘要不能更改这些状态。

历史加载过的 skill 正文不作为独立上下文恢复，不生成 `arkcode-active-skills` 消息。保留的真实用户文本仍可包含原始 `/skill:name` 或 `@skill:name`，但重建时不会重新展开；当前 Skill 目录和停用状态按现有机制更新，模型可根据任务和历史 query，使用 read 按需读取当前仍允许访问的 Skill。尚未交付的新 query 保留其正常展开的正文，不因 compact 删除。程序不凭摘要生成新授权。

将完整上下文基线写入检查点并同步差量比较基线。后续 prepareRequest 在确有变化时追加 diff，避免一恢复就重复注入 full。重启后允许根据当时实际环境追加新的 diff。历史事实由摘要交接，当前文件和进程状态需要按任务验证。

## 调度与并发

自动压缩、手动 /compact 和 overflow 恢复进入同一个 ArkCode 压缩模块，传入 reason、cutoff、model、signal 和待追加输入。首版同一会话只允许一个压缩操作，不做后台异步摘要。

新 query 在 pre-request 压缩时位于 cutoff 之后，摘要不处理它。loop 压缩将刚收齐的工具结果纳入 cutoff。两种情况都通过正常 loop 入口继续，不构造新的用户任务。压缩期间输入按 inputId 排队并持久化，提交后按原顺序追加一次。分支或模型改变会使候选失效，不能装到另一份历史上。

空闲状态 /compact 完成后仍为空闲，不自行生成回答。执行中不在半条响应或未闭合工具调用上强制安装；保持当前 CLI 的命令使用约束。已取消的调用由执行层记录实际取消结果，摘要不能补造成功结果。用户明确取消运行时，压缩不把已取消任务自动恢复。

没有新增历史且没有上下文或待生效工具配置变化时返回 no-op。存在待生效配置或上下文变化、但没有新对话时，手动 /compact 可以复用上一摘要构建刷新检查点，不调用摘要模型。旧检查点包含 `arkcode-active-skills` 时同样执行刷新，在新检查点中移除该块而保留原始 JSONL。刷新检查点要求完整请求低于目标，不要求工具切换后一定比旧请求更小。没有可复用摘要的空会话沿用首次请求前应用配置的现有规则。

## 检查点、提交与恢复

继续使用现有 type=compaction 的 JSONL 条目。在有版本的 ArkCode details 中保存 replacementMessages、保留原文范围及来源、cutoff、待处理与已交付的 inputId 状态、上下文基线、工具策略快照、触发原因、模型、预算与裁剪诊断。区分摘要检查点与无模型调用的刷新检查点。保留现有 summary、tokensBefore 和 usage 字段供 UI 展示。工具快照不保存凭据或连接秘密。

replacementMessages 是实际候选模型历史，包含来源类型。它是恢复顺序的依据。firstKeptEntryId 不能表达任意过滤与重排，不再用于推导新规范的布局。Pi 原始投影只用于读取 legacy 历史，ArkCode 新检查点由统一投影恢复。工具目录发现出的临时声明按当前工具机制重建，不能从旧摘要认定工具仍可调用。

提交顺序如下。

1. 捕获分支、cutoff、输入和当前配置版本，构建只读快照。
2. 生成摘要，在临时区域准备新的上下文与工具配置。外部依赖准备失败时不提交。
3. 校验候选的完整预算、来源、工具配对和版本。确认分支、模型和依赖版本未发生冲突。
4. 通过会话单写入队列追加一个完整检查点并完成刷新。压缩期间的 pending 输入使用独立记录，不因检查点覆盖。
5. 将已准备的历史、差量基线和工具策略激活，随后发布完成通知、更新 UI 并继续执行。

JSONL 和 MCP 外部副作用没有跨系统事务。提交前失败保留旧状态。若检查点已经写入，而激活异常或进程退出，持久化检查点仍是权威状态；阻止模型请求，重试激活或在恢复时完成，不能宣称已回滚旧历史。写入结果不确定时先检查记录是否完整存在，再决定，避免重复提交或错误回滚。新运行时拒绝不认识的检查点版本。

resume 从当前分支最近的有效检查点恢复 replacementMessages，再追加 cutoff 后的有效后缀。已经持久化但尚未纳入模型历史的 pending 输入按交付状态恢复，不能只根据它在文件中位于检查点之前还是之后判断。按 inputId 去重。fork 按其分叉位置恢复，不读取其他分支的新配置。旧记录仍留在文件，聊天 UI 不因模型上下文替换而隐藏原始对话。运行中和恢复后在相同外部环境下使用等价的模型历史。

## 旧会话兼容

旧会话没有 ArkCode 检查点时，先用现有 Pi 有效投影读取当前分支，原有摘要继续作为摘要输入，不回退到原生 compact 生成流程。识别已有环境 customType、compactionSummary 和 branchSummary，排除它们作为人工输入。

无来源字段的普通 legacy user 消息按现有已知封装规则还原可见文本，标注 legacy，之后保存稳定的保留范围。不能从文本准确判定的来源不伪装成已验证 human。该兼容路径尽力保留旧 query，但无法保证清除所有历史上的生成内容。首次压缩显示一次兼容提示。新输入从入口捕获来源，避免继续积累歧义。

## 实现归属

ArkCode 模块拥有预算判断、用户选择、摘要提示、临时裁剪、候选验证和检查点组装。Pi 保留供应商序列化、工具执行调度和通用会话能力。需要最小的宿主入口支持完整候选历史的安装与统一恢复，不能只用 session_before_compact 覆盖 summary。

原生自动阈值、原生摘要路径和 ArkCode 新策略不能同时运行。通过已有校验和 Pi 补丁流程暴露必要入口，避免散落的运行时 monkey patch。同步更新手动入口、loop 续接、resume、fork、UI 和工具配置恢复的读取路径。

## 验收范围

实现阶段使用真实 Pi SDK 和本地模型协议服务验证行为，不需要远程付费模型。

- 真实输入来源覆盖普通 query、代码日志、显式 skill、steering、follow-up、媒体混合与控制命令。
- 20k 选择覆盖完整保留、边界首尾截断、超长单条、中英文与 emoji、空文本、连续两次压缩、标记预算与来源范围。
- 触发覆盖 90%、50k、输出预留、tools 和媒体开销、新 query、小窗口、模型切换以及过期 usage。
- 摘要覆盖空响应、截断、工具调用响应、临时网络错误、有限重试与取消。
- 裁剪覆盖 8192 精确边界、跨 text 块、多次应用、非文本顺序、元数据和错误状态不变，原始历史条目未被改写。
- 生命周期覆盖 pre-query、loop 续接、并行工具收齐、排队输入、显式取消、手动空闲和无进展失败；压缩失败后容量允许则继续、实际 overflow 则暂停，并可在原会话恢复。
- 持久化覆盖运行时与冷启动请求一致、fork、旧记录兼容、未知版本、写入失败和提交后激活中断。
- 工具配置覆盖成功应用、提交前失败不应用、提交后恢复激活、无新增对话时刷新，以及新 system 与 tools 使用同一配置。
- UI 显示压缩原因、结果、失败和提交后待恢复状态，不显示内部上下文消息。

## 后续优化和已知限制

历史查询与 window 提示、专用历史读取视图、后台压缩、近期 assistant/tool 尾部、自动小窗口预算适配和自动媒体外置均不在首版。保留媒体任务状态不等于保留媒体原始内容。

摘要有损，连续多次压缩可能遗漏细节。工具裁剪可能删掉中间的唯一错误信息，头尾保留不提供语义完整保证。原始日志保留不等于 agent 拥有检索能力。没有远程模型实测时，不声称摘要续接成功率、供应商 token 估计误差或 prompt cache 命中率已经验证。
