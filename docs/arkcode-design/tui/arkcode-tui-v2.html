产品边界

一个终端里的编码助手，围绕一次改动组织。

目标用户已经在终端和编辑器中工作。ArkCode 负责把自然语言任务变成可检查的代码与执行证据，完成后让用户继续自己的编辑器和 Git 流程。

过程紧凑，证据可打开。

阅读、搜索、编辑用简短记录。执行命令和错误保留可访问输出。最终回复说明变更、验证范围与未完成事项。

输入只有一个发送含义。

空闲时 Enter 发送。运行中普通文字留为草稿，完成后仍须用户发送。Tab 只补全，恢复历史也不会再次执行。

批准对象与执行对象一致。

用户批准具体命令、目录与 shell。批准只适用于一次工具调用。停止撤销挂起批准，迟到的按键不会启动旧命令。

终端习惯优先。

保留原生 scrollback，退出后回到原 shell。没有常驻项目树、代理列表或活动仪表盘。复杂信息在需要时进入面板。

本规格替代前一报告中 Electron、React 窗口与桌面单实例的入口假设。Pi 历史、运行准入、审批、停止与审阅的所有权继续沿用。TUI 宿主监督一个 SDK worker；每次启动固定一个目录。不同目录可开不同终端，同目录只有一个可写宿主。

借鉴与判断

参考交互的理由，并重新确定边界。

官方文档核实用户操作，固定提交源码核实实现。两者均在 2026-10-09 查阅，默认行为可能随版本变化；以下 ArkCode 规则均为提案。

参考中的事实ArkCode 沉淀出的规则选择的代价
Codex 将目录、模型、权限与命令入口放在终端会话附近。D01D02启动条交代目录；输入区附近保留模型、模式与运行状态；设置按需打开。不常驻显示所有诊断。详细信息需要 /status。
Codex 的工具摘要与详情不同，某些详情仍标明采集截断。C5C6区分“显示折叠”和“实际未采集”；失败首先展示退出码和尾部诊断。必须管理输出文件、大小限制与过期规则。
Kimi 提供 / 补全、文件引用、审批以及多种权限模式。D04复用输入与选择器习惯；只保留只读/编码，shell 逐次批准。命令密集任务会多次批准，首版不提供会话内一律允许。
Kimi 的会话恢复、压缩与导出各有独立操作。D05/new、/sessions、/compact、/export 含义独立；恢复对话不宣称恢复副作用。无法自动接续上次未知命令，需用户重新交代下一步。
本地 Codex HEAD 的 alternate-screen 是 auto；Kimi 默认 regular；Pi 提供两种 renderer。C10K1P1首版明确选 regular 单列，复用 TuiMainScreen。全屏留待实际需求。终端掌管历史滚动。ArkCode 无法可靠显示全局“有新输出”或冻结原生滚动位置。
为什么不直接复制同名功能和快捷键？

Codex 的运行中 Enter / Tab 与 Kimi 的 Ctrl+S 追加输入依赖各自执行模型。ArkCode 尚未实现队列的交付、保存与取消契约，首版只保存草稿。D02D06

Codex 的 /review 是模型审查，/diff 是本地差异。ArkCode 以 /changes 打开事实审阅，AI 审查稍后再做。不同文档对 Ctrl+D 的说明也有差异，ArkCode 明确将它定义为编辑按键，退出使用 /exit。D02D06

首次运行与入口

从当前目录开始，先确认配置与写入范围。

安装与启动要能在没有 Git、网络不可达和非 ASCII 路径中给出明确反馈。下面是产品接口提案，命令尚未发布。

CLI 接口

arkcode                         # 当前目录，新会话
arkcode -C "D:\项目\checkout"   # 指定目录
arkcode -c                      # 当前目录最近可恢复会话
arkcode resume                  # 当前目录会话选择器
arkcode resume <session-id>      # 恢复指定会话
arkcode --plain                 # 无 ANSI 的交互降级
arkcode --no-color              # 保留交互，关闭配色
arkcode --help / --version

首版建议 npm 分发，锁定受支持的 Node LTS 与 SDK 版本；最低 Node 版本以打包验收确定。首版不接受 -p、--yolo 或后台 daemon，非 TTY 时在调用模型前退出并解释当前仅支持交互模式。

首次配置流程

  1. 解析真实目录，检查读取权限、Git 状态与工作区锁。没有 Git 仍允许继续。
  2. 没有有效模型时打开 provider 配置。选官方 provider 或 SDK 支持的兼容协议，填写端点与模型。
  3. 密钥优先读取显式环境变量。持久保存优先使用系统凭据存储；不可用时提示选择仅本进程使用或权限受限文件。
  4. 校验连接，显示实际 shell 及编辑器。校验只发送认证/最小测试请求，不发送项目文件。
  5. 首次目录选择只读或编码。默认选只读；用户显式选编码后保存目录偏好。
  6. 显示已有文件改动，输入第一个任务。首次含模型请求时再建立持久会话。
启动状态界面与动作必须保留的事实
新用户 / 未配置进入配置面板；取消可退出，不建立空会话或上传文件。当前目录，凭据来源，端点 / 协议。
目录已有修改启动摘要写“已有 3 个文件修改”；可 /changes 查看全量。无需额外逐文件批准读取。后续运行基线包含 staged、unstaged、untracked。
同目录被占用只读浏览历史/差异，显示占用 PID 和开始时间；禁止发送、新会话写入与设置会话元数据。不得仅凭 PID 文件删除锁；先核实进程身份和旧命令。
恢复中断会话显示历史、当前文件和未知命令；无法确认旧命令退出时执行锁定。新 epoch，旧审批全部失效，草稿标为“未发送”。
认证 / 端点失败说明无效凭据或网络问题；可编辑配置、重试或退出。保存草稿，日志与错误不泄漏密钥。

配置优先级建议为启动参数 > 显式环境变量 > 用户设置 > 产品默认；项目只保存文本指令与已确认目录偏好，不自动读取可执行项目扩展。恢复会话不能覆盖本次明确配置。

界面构成

连续对话，加上可以被临时替换的输入区。

主界面是终端主缓冲区中的连续文档。启动摘要仅出现一次，可以随记录滚走。状态、输入和提示位于当前文档尾部，不承诺永久固定顶栏。

区域信息层次与尺寸交互
启动摘要4 行以内；版本、目录、分支与脏状态、会话标识。首次配置只出现必要项。完整路径与诊断可 /status 查看；不重复打印 logo。
对话记录用户正文、助手正文、工具摘要、结果。短段落，代码保持等宽，长工具输出折叠。终端原生滚动与复制；被重新渲染的当前尾部不承诺永久位置。
状态行状态词 + 当前动作 + 活跃耗时；等待批准不显示“执行命令中”。无进度数据不用百分比。来自 SDK / 宿主事件；运行结束后加入结果摘要。
输入区默认 3 行含边界，随正文增长到 6 行；更长内容内部滚动。候选菜单不挤没输入光标。多行编辑、补全、粘贴、历史、外部编辑器。运行中保留编辑能力。
提示行优先显示模式、模型，再显示上下文；窄屏先隐藏推理等级与非必要指标。只提示当前焦点真正生效的按键。静态帮助从同一命令/按键注册表生成。
临时面板最大使用可见区域，审批至少保留目标/范围/拒绝/详情。列表每页按剩余行数计算。方向键、Enter、Esc；返回先恢复原草稿，禁止把确认键透传到输入区。
颜色、字符与状态词

默认跟随终端背景，不强制全屏铺色。主题只有明、暗、无色；用终端前景为正文，弱色为参数，青色为完成，琥珀色为批准/警告，红色为失败。状态同时有文字，不能只靠色彩。

终端界面用 ›、✓、×、! 辅助阅读，ASCII 降级使用 >、OK、ERR、!。不使用 emoji 作状态或 spinner。按 grapheme 与终端 cell width 排版，不能按字符串长度截断中文、组合字符或路径。代码行可以水平分页，说明文字换行。

输入与上下文

先让用户确认进入模型的文字和文件。

ComposerDraft 保存正文、粘贴载荷与显式文件引用。命令菜单与输入历史都只改变草稿，直到用户提交。控制命令走宿主，不进入模型对话。

普通任务与命令解析

  • Enter 提交前验证目录锁、模型、当前模式和输入大小；失败时保留完整草稿。
  • 首个非空字符为 / 时解析本地命令；未知名称显示错误，不默默发送给模型。若要发送以 / 开头的文字，用 // 转义，提交时移除第一个 /。
  • 输入 / 打开菜单，匹配名称与描述。Tab 插入命令名称；Enter 在菜单中确认候选，不再自动执行。完整命令在输入区再次 Enter 执行。
  • 运行中的普通 Enter 留为草稿，并提示“当前任务进行中，草稿尚未发送”。任务结束不会自动发送。
  • 首版无 ! shell 模式。要自行操作项目，另开终端；ArkCode 的 shell 始终作为可批准工具执行。

@ 文件引用

  • 搜索工作区相对路径，尊重忽略规则，排除 .git、node_modules 与明确敏感文件。目录只用于导航，不整目录塞进请求。
  • 候选确认形成可识别文件引用，而不是隐含上传。支持 @"含 空格/checkout.ts" 和可选行段 #L10-L30。
  • 提交时解析真实路径，拒绝逃出工作区的符号链接，显示读取范围和大小。文件已经变化时发送提交时版本。
  • 建议单文件不超过 256 KiB，总显式引用不超过 1 MiB。超限给出选择行段的入口，不静默截断。二进制/图片暂不支持。
  • 实际读取成功的内容与来源进入本次上下文；历史召回路径必须重新校验。敏感文件被排除并给出原因，首版不提供隐藏放行。
操作规格失败 / 边界
多行与粘贴bracketed paste 原子插入；超过 8 行或 2,000 字符折叠为“粘贴 N 行”，保留原文与展开入口。整体提交上限建议 64 KiB 文本。粘贴中 Enter、Tab、/stop 都是文字，不发送、不批准。不支持 bracketed paste 的终端需经过验证的检测或 plain 模式安全粘贴入口。
中文输入法组合阶段不发送；提交候选只完成文本输入。terminal backend 需验证实际 IME 编码，不能套用浏览器 composition 事件。原型只验证浏览器输入契约，原生 Windows Terminal 仍需测试。
历史Up/Down 在编辑边界召回当前目录已发送文本；Ctrl+R 检索。取消恢复搜索前草稿。未发送草稿不冒充历史；引用和粘贴载荷丢失时不能只恢复占位符。
外部编辑器Ctrl+G /open 使用显式配置或 VISUAL > EDITOR。暂停 raw mode，使用 argv 启动；返回后恢复终端和原视图。编辑器退出失败保留原草稿和临时文件恢复入口。禁止编辑器字符串拼接 shell。
草稿保存每个会话有本地草稿 sidecar；短延迟原子替换，标记未发送。首次尚无会话时按工作区保存。不保证断电零丢失。只读占用浏览器不写 sidecar。认证面板的密钥不进入草稿。
文本指令/context 列明读取的 AGENTS.md 与用户明确选择的文本来源。当前运行开始后固定来源及工具集合。项目内容不能设置凭据、批准工具或执行扩展代码。首版敏感文件 deny 规则属于文件工具策略，不是整个 shell 的 OS 沙箱。
执行与反馈

运行状态与验证结果使用两套事实。

任务可能已结束但验证失败，也可能已写入文件却未执行测试。界面同时表达执行是否空闲、改动是什么和验证到了什么范围。

阶段显示内容用户能做什么
准备检查目录、建立文件基线、固定 model/mode/tools、分配 runId。可停止；重复提交返回原运行身份，不能开始第二个。
模型输出助手流式正文与“正在分析”；不显示未经执行的“已测试”。写下一条草稿，打开状态/上下文/已有改动。
工具执行read/search 用路径与计数；edit/write 用文件及统计；shell 用命令、开始时间和实时尾部。Ctrl+O 详情；查看面板关闭后当前运行继续。
批准等待“等待批准”，展示完整最终参数；耗时是等待时间，命令未开始。允许一次、拒绝一次、停止整个任务。草稿暂不获取键盘焦点。
重试 / 自动压缩真实重试次数或“正在压缩”；有已知延迟才显示倒计时。停止。不开放新建、切模型或权限变更；普通输入仍留草稿。
结果整理收集最新文件差异与命令结果；直到工作区可安全再次使用才释放运行槽。查看证据，不能提前提交。
空闲变更摘要 + 验证通过/失败/未执行/未知 + 后续事项。主动发送草稿、新会话、切模型、导出或自行接手。
工具串行是 ArkCode 的显式配置。运行前设置 session.agent.toolExecution = "sequential"，不另建工具调度器。拒绝一次工具不会保证模型立即结束，它可以解释或调整方案；UI 仍等待真正 settled。A21

输出密度

连续读取与搜索可以合并显示计数，原工具身份仍可展开。命令运行只更新最多 4 行尾部；结束显示 exit code、时长和至多 6 行关键输出。失败保留诊断，不只显示红色图标。

输出全文建议写 sidecar 工件，每次调用上限 10 MiB，达到上限保留首尾并标“采集已截断”。会话只保存 SDK 所需结果与工件引用。超过保留期限后详情标“日志已清理”，不称完整日志。

模式与批准

先确定编码范围，再批准一次具体命令。

只读/编码是能力选择，shell 批准是一次执行决策。二者独立。首版没有 YOLO、永远允许或“按 Enter 放行所有操作”。

模式自动允许需要批准 / 不提供如何进入
只读受控 workspace read、搜索、查看历史、当前 diff。无 shell、edit/write。分析回复仍可消耗模型 token。新目录默认选择；/permissions 空闲时确认。
编码本次提交授权工作区根内的受控 edit/write；工具边界仍验证路径与 deny 规则。每次 shell 请求批准；根外写入与敏感文件拒绝。shell 不受文件工具路径规则完全隔离。用户显式选择后，再用 Enter 发起本次编码任务。

长命令与故障

  • 命令、cwd、shell 与一次性范围不可被摘要隐藏。过长参数进入分页详情；显示不完整时允许入口禁用，查看完整参数后再返回选择。
  • 审批绑定 epoch、sessionId、runId、toolCallId、最终参数摘要。失效或不一致只返回过期结果。
  • Esc 拒绝本次工具，Ctrl+C 请求停止整个运行。两者都不会回滚已经写入的文件。
  • 在当前查看面板中到达批准，保存面板位置与草稿，批准接管焦点；处理后可返回原查看面板。
  • 批准等待无自动允许超时；宿主退出、worker 失联或停止会撤销等待。

批准 broker 由宿主管理，SDK hook 只请求决策。仅加载受控处理器，避免批准后参数再被修改。worker 隔离是故障隔离，不是 OS 沙箱；所有 shell 都必须显示当前用户执行权限。A12A13A17A18

模型主动提问如何呈现？

首版不新增结构化 AskUser 工具。模型问题以普通助手正文显示，在 settled 后由用户回复。工具批准面板只处理执行许可，不能把需求回答伪装成工具授权。结构化问题与 Plan 模式有明确需求后再引入。

改动与证据

每个差异都交代比较的两端。

/changes 是本地查看，不调用模型审查、不再次应用补丁。默认比较最近运行前的文件基线与当前文件。工作目录全量与命令证据分别切换查看。

视图用户看到什么允许的操作
运行增量基线时间 → 当前时间；modified/added/deleted、增删行与“来源可能混合”。运行中显示“未定稿”。选择文件，逐段 unified diff；n/p 下一/上一文件；Esc 返回。
工作目录全量Git 下区分 staged、unstaged、untracked；同一文件可出现在多个类别。显示 rename、二进制、删除和不可读取。切换分类查看，不 stage/unstage，不重置文件。
非 Git 目录只能有已采集运行基线的增量；首次启动全量说明无 Git 比较基准。查看本次运行采集文件；未建立基线的文件不编造全量差异。
命令证据 /checks命令、cwd、shell、起止时间、exit、取消/拒绝/未知、采集限制、验证范围与新鲜度。打开输出，复制命令文字。复制不会执行；首版不提供一键重新运行。
工具记录详情执行参数及那一次工具结果，不等同于当前工作目录所有变化。分页与本地搜索；过期工件明确标记，模型可见摘要和本地原始输出有区别。

审阅操作

先选比较范围，再选文件。文件列表保持路径、状态与来源说明；增删行是辅助信息。宽窄终端都使用“文件列表 → 单文件 diff”的同一流程，首版不做双栏 side-by-side diff。

diff 中 Up/Down 按行、PgUp/PgDn 按页，n/p 切文件，/ 搜索当前内容。长代码行水平移动，不截掉导致行为变化的字符。返回列表保留选择与页码。

证据新鲜度

测试通过只证明当时命令在对应文件状态下 exit 0。后续文件变动使证据标为“可能过期”。已知验证输入保存指纹；无法精确识别依赖时任何工作区源码变化都保守标记可能过期。

运行基线只覆盖可观察文件变化。用户外部编辑或 shell 期间变更标来源可能混合。没有足够依据时显示未知，不宣称全部由 Agent 创建。

基线采集应有预算。建议单文件 1 MiB、单次基线总内容 50 MiB；大文件保留 hash/大小而不生成正文 diff，超预算明确列出未覆盖路径。二进制、忽略目录和删除文件显示状态。预算是首版建议默认值，待真实仓库验收调整，不能以跳过采集掩盖变更。
会话与长对话

对话能继续，旧命令不会随恢复再执行。

Pi SessionManager 仍是会话事实的唯一来源。ArkCode 只保存索引、草稿、批准、运行收据与变更工件。会话索引可重建，不另设第二套 messages 数据库。

停止、退出与恢复

收到停止请求，与确认停止，是两个状态。

Esc 在输入区或 Ctrl+C 请求停止；界面立即响应，但只有审批、SDK 和受管命令都收敛后才能开放新任务。已完成的写入保留。

  1. 宿主进入“正在停止”，不再接受新运行，固定本次取消意图。
  2. 审批 broker 撤销等待，拒绝迟到批准；把尚未提交输入保留为草稿。
  3. 调用 SDK abort，显式处理队列。首版不入 steer/follow-up 队列。
  4. 监督 shell 及子进程退出；worker 退出本身不能证明命令停止。
  5. 保存可保存运行收据，刷新真实 diff。确认完成则显示已停止；无法确认则显示停止未确认并保持执行锁。
动作 / 事件产品结果后续入口
停止超过 5 秒变为“仍在停止”，列明等待的是审批、SDK 或命令。5 秒是提示阈值，不是强行解锁。查看状态/当前改动。首版不把第二次 Ctrl+C 当作强制退出捷径。
等待批准时退出先用 Ctrl+C 或“停止整个任务”撤销批准并停止，再执行 /exit。审批焦点不接受普通命令输入。只有清理确认后退出。普通运行输入区可用 /exit 打开停止并退出确认。
退出锁定的只读查看器被占用目录的查看器可退出，不影响另一宿主。恢复查看器退出时明确提示旧执行仍未知。不写会话/草稿，不移除执行占用，不宣称旧命令已清理。活跃执行宿主仍须确认停止。
空闲退出有草稿先保存或明确放弃；失败给出重试、导出草稿和明确放弃。恢复终端 raw mode、鼠标/键盘协议与光标，输出短摘要、sessionId 和恢复命令。
worker 异常宿主仍能显示中断；不自动重启并续跑。存储不一致保留未知状态。确认旧命令退出后重建 worker，只由用户新指令开始运行。
整个 TUI 宿主崩溃重启先校验工作区占用和受管命令；确认退出前只读展示历史。Windows Job Object 等机制作为实现候选，需验收崩溃清理。不能通过删除锁文件解锁。
存储写入失败显示“记录未确认保存”，后续有副作用的任务暂不启动；文件可能已经变化。重试保存、检查目录、导出能读取内容。流式 message_end 不作为保存确认。A05

普通 /exit 成功为进程 exit 0。启动/配置致命失败为非 0。运行测试的 exit 1 是工具事实，不自动作为整个 TUI 的退出码。强制结束 OS 进程属于用户外部操作，重启必须按中断处理。

/permissions只读 / 编码仅空闲改变后续运行。编码模式按本次提交允许根目录内 edit/write；shell 仍逐次批准。

/checks命令与验证证据运行中可用本地查看。看命令、cwd、shell、时间、退出码、输出、文件指纹及是否过期；不会再次执行。
/context指令、显式文件与上下文占用运行中可用本地查看。标明 AGENTS.md 路径、附加文件和最近压缩；无完整 usage 时显示未知。

/copy复制最近完整回复运行中可用本地剪贴板。不复制未完成流；剪贴板不可用时提示使用 /export，不回显敏感内容。

终端与无障碍

空间少了，优先保留任务和操作对象。

常规模式是首版默认。终端掌管 scrollback，面板只占当前可见区域。无色与 plain 的作用不同；前者仅移除颜色，后者同时避免光标控制与弹出菜单。

条件布局与输入保持可用
≥ 100 列，≥ 24 行完整模型/模式/上下文状态；列表带描述；正文不超过约 100 列，代码单独处理。单列对话与逐文件 diff，不增加固定侧栏。
60–99 列，≥ 18 行描述换行，简化非必要配置；面板页数按高度计算；编辑至少保留 3 行。完整命令/路径可分页访问，批准对象与拒绝选项可见。
40–59 列或低于 18 行紧凑面板一次一个信息块；详情分页；隐藏 logo 和测试统计等辅助内容。如果批准目标无法完整访问，允许禁用；停止和拒绝仍可操作。
< 40 列或 < 8 行显示“终端过小”，保留当前状态与 Ctrl+C。尺寸恢复后重绘，草稿和选择不丢。不批准、不开始新任务。不能因此释放工作区锁。
--no-color / NO_COLOR无色但仍使用交互组件；状态词、符号和边界保留。颜色不承担唯一信息。
--plain / TERM=dumb顺序文本 + 行输入；命令参数直接输入；菜单打印编号。多行用显式 /paste 与独占一行的 /end 采集。采集内 //end 转义为文字 /end，其余行不解析命令。结束后仍需显式发送确认。批准输入完整的 allow <request-id> 或 deny <request-id>；默认拒绝，不接受裸 y。/paste、/end 仅作为 plain 输入控制符，不是模型命令。

实施与验收

先走通任务，再验收输入、失败和终端边界。

详细规格不意味着所有功能同一天实现。下面三段都在首版闭环内，复杂功能继续留在范围外。无工期和性能数字承诺。

第一段

真实编码闭环

启动、模型配置、目录锁、单列输入、流式正文、受控工具、逐次批准、停止、结果与 diff。

小型真实仓库中完成修改与测试；拒绝后命令未执行；停止等待审批可结束。

第二段

可重复日常工作

草稿、@ 文件、提示历史、会话恢复、逐文件审阅、输出工件、/checks、上下文与压缩。

dirty workspace、外部编辑、worker 中断和存储故障都能正确接手。

第三段

终端发布质量

中文 IME、粘贴、resize、无色/plain、外部编辑器、凭据存储、Windows 子进程清理、导出。

所有基础键盘路径可用，未知停止不放新运行；终端退出后恢复 shell。

长命令在 40×8、80×24 中批准可访问完整对象、cwd、shell 与范围；无法查看完整参数时允许禁用。
SDK retry、auto compact、同批双工具同一次运行，agent_settled 才结束，工具显式 sequential。
同目录从两个终端启动真实路径 alias 也识别为同目录；一个 writer，另一个 viewer，不重复写 JSONL。

staged、unstaged、untracked、非 Git、大文件与二进制比较范围正确，未覆盖路径可见，没有虚构归因或差异。
测试 exit 0 后外部改文件/checks 证据变为可能过期，模型文本不能写通过状态。
输出超过限制，含 ESC/OSC 链接与剪贴板序列采集截断可见；内容不能改控制面板或剪贴板；日志不能假称完整。
