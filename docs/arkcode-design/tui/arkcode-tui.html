ArkCode TUI

沿用 Codex 的操作习惯，减少切换工具的学习成本。英文界面、克制的视觉层次，以及可靠的编码执行。

底座仍为 pi-coding-agent SDK。本文是最新产品提案与静态界面样稿，替代上一版权限、输入和命令规则。尚未实现原生 TUI。

界面渲染权限操作功能与命令工作流程实现依据

熟悉的交互，ArkCode 自己的界面

结构以 Codex 为准。启动只保留 ArkCode 标识，正文是连续对话与紧凑工具记录。模型、推理等级、目录、权限、分支和上下文用量常驻 composer 下方，默认不显示发送与换行提示。面板按需出现，不增加常驻侧栏。产品文字全部使用英文；用户输入、文件内容和模型回答保留原语言。

Apple 美学在终端里的转译

通过留白、对齐、轻边界和稳定的层次降低阅读负担。正文最醒目，参数稍弱，帮助最弱。强调色只用于当前选择、焦点与必要状态。终端沿用用户字体和背景，默认跟随终端明暗与无色设置。

ArkCode 的识别来自短启动标识、精确缩进和细分隔线。正文不包进反复出现的方框，运行输出不堆装饰性徽章。网页样稿的圆角不要求原生终端画圆角或强制铺背景。

Codex 定交互，Kimi 补视觉细节

采用 Codex 的 •、└、› 层次与紧凑记录。参考 Kimi 的角色色与加粗强调用户 query，composer 使用明确边界、淡底色和焦点色。底部六项会话信息常驻，窄屏换行，不为快捷键提示让位。命令名、快捷键与权限语义仍以 Codex 为准。

工具输出默认显示动作、对象和关键结果。详细转录保留完整已采集内容。失败用 Failed 和退出码表达，颜色只是辅助；没有实际用量时显示 Context unavailable。demo 的 18% 用量来自固定样例，不是实测。

原生布局按终端单元格计算。内容左右留 2 列，正文建议不超过 100 列；段落之间 1 空行，工具子项缩进 2 列。只使用常规与强调两种文字权重，不引入 TUI 专用字体下载。复杂记录由 Ctrl+T 进入详细转录。

默认视觉采用 Instrument 的细线结构与 Deep field 的稀疏颗粒，默认配色使用精简后的 Prism。终端与 composer 使用纯黑背景；工具动作、路径、命令、Markdown 和代码以白灰呈现。composer 使用 8px 圆角与常驻淡紫边框，淡暖灰区分用户输入，红绿保留增删与测试语义。底部六项信息保持低饱和角色色。颗粒限于页边和头部留白，不叠加在正文上。普通输入进入 composer，审批面板与快捷键按自己的操作语义处理。

让推理、行动与结果各自清楚

主视图优先呈现用户需要判断的事实。沿用 Codex 的活动摘要与转录分工，参考 Kimi 的短结果预览和组件复用。交互 demo 展示以下规则，原生终端仍需单独实现。

内容渲染规则落地边界
推理与活动底部一行活动标题、耗时和中断提示。只使用模型实际返回的可展示摘要；没有摘要时显示 Working。完整可见摘要用弱色、斜体留在 Ctrl+T 转录中。不编造思考过程，不把等待工具标成模型思考。摘要更新保持同一记录身份。当前工具状态优先于推理标题。
工具调用Exploring → Explored，Running → Ran，Editing → Edited。相邻文件读取合并为探索组；shell 命令与编辑各保留独立身份。子项用 └ 和固定缩进。由 toolCallId 关联开始、增量和结束，不能靠文案匹配。调用工具不代表执行成功；工具返回不代表整个 Agent 已收敛。
工具结果普通 shell 默认保留约 3 屏幕行预览，显示省略数量，详细转录可展开。失败保留错误原因、位置和 exit code，成功标记仅用于真实成功事件。浏览器 demo 用 3 个逻辑行近似；原生版本按终端显示列宽计算。输出是文本，控制序列须过滤。完整已采集输出与展示截断分开，存储截断必须另行说明。
Markdown 与流式输出小标题保持终端文字尺度；列表悬挂缩进，引用弱化，表格窄屏单独横向滚动。已完成块稳定提交，末尾块可更新；未闭合代码围栏仍能显示代码。使用 Pi 的 Markdown 能力和成熟解析器，保留原始 source。先按内容块批量刷新，再优化更新频率。不得逐 token 拼接 HTML 或重复刷整份历史。
强调、代码与 diff加粗表达重点，inline code 用克制强调色。代码采用语言语法色；diff 用 + / - 和绿 / 红共同区分增删，保留文件与定位。文件引用可打开定位预览。代码未知语言回退纯文本；复制使用原始内容。主题改变语法色，不改变权限、成功或失败的含义。颜色不足时，状态文字和符号仍完整。
动效与滚动只有当前活动标记有轻微亮度变化。完成即停止，不闪整行、不移动旧记录。用户位于底部时跟随新内容，查看历史或选中文字时暂停跟随。这是 ArkCode 的动效取舍，未照搬 Codex 的 shimmer。支持关闭与系统减少动态效果。界面后台不继续播放 demo；原生渲染缓存以内容修订、宽度和主题为键。

交互 demo 的范围。 可播放、暂停、逐事件前进、重置和切换明暗。运行时支持 Enter steer、Tab follow-up、中断与草稿恢复；审批支持允许、会话放行、拒绝、取消与键盘选择。Ctrl+T 查看摘要与完整输出，Ctrl+O 复制完整回答。输入 /diff、/review、/copy 可查看对应样例。

所有工具结果、文件定位与审查都是固定样例。demo 不连接 Pi SDK，不证明实际沙箱、存储与原生快捷键已实现。浏览器可能保留系统快捷键；顶部转录按钮与输入 /copy 提供等价入口。

源码依据与首版实现方式

Codex 把可见推理摘要更新到活动标题，并留在转录中。参见 streaming.rs。当前紧凑 shell 输出预览约束来自 tool_output.rs，不是其他渲染路径中的 5 行常量。

Codex 的 流式控制器 保留提交区域与可变尾部，活动行 单独控制进度与 shimmer。主题参考 OpenAI Docs · CLI customization。

Kimi 的 thinking.ts 与 rendering.ts 使用短预览，复用组件与缓存。其 Ctrl+O 展开语义见 官方交互文档，ArkCode 继续使用 Codex 的复制键位。

首版原生渲染直接复用 Pi Markdown 的 source 与 width 缓存。ArkCode 负责事件到显示记录的投影、分组和状态，不另建 Agent 循环。浏览器样稿内嵌 Marked、highlight.js、DOMPurify 与 Lucide 图标，构建后是一个自包含 HTML。

以当前 Codex TUI 的 Read Only、Ask for approval、Full Access 为主名称。Ask for approval 对应官方安全文档中的 Auto 预设。这里的“询问”指越过授权边界，不是每条 shell 都询问。依据

确认后写入 Permissions updated to Full Access。默认只改变当前会话，不顺带改变全局默认。不弹出逐次命令审批，也不暗设“Full Access 但继续询问”的另一套行为。受管策略禁止时显示禁用原因。

运行中允许打开 /permissions 与 /model。新配置在后续动作的安全边界生效，已启动的命令继续使用启动时的快照。界面区分选择值与实际生效值；有尚未结束的动作时显示 Applies after the current action。不能让一次进行中的命令因切换模式获得更大权限。

审批只出现在明确的额外授权处

可用决策由请求类型给出。一次允许绑定最终命令、目录和请求身份；会话授权还绑定命令参数或具体网络目标。长期前缀规则另需用户明确选择，首版可以后置，不拿“本会话允许”冒充永久规则。数字快捷键、方向键和 Enter 按 Codex 习惯确认，但粘贴与重复按键不能生成审批动作。

这次产品选择带来的必要调整。 Pi SDK 自身不提供 Codex 等价的 OS 沙箱。只靠权限 hook 或命令字符串检查，无法兑现上面的 Auto 与 Read Only 行为。真实沙箱执行层因此进入首版必需范围；平台执行层未就绪时，对应模式显示 Unavailable: sandbox not ready，不静默退化为无隔离执行。

输入习惯也迁移过来

不再保留上一版“运行中 Enter 只保存草稿”的自定义含义。快捷键按焦点处理，优先级为审批、面板与候选、普通输入区。一次按键只消费一次。

操作ArkCode 行为边界
Enter · 空闲提交任务；候选菜单内确认候选。已选中的无参数命令按 Codex 直接执行。需要参数的命令把光标放到参数位置。Tab 补全命令名，不提交。
Enter · 执行中将新指令作为当前轮次的 steer 输入，显示 Instruction pending，SDK 消费后转为对话记录。“立即提交”不等于终止正在运行的工具。工具完成后进入可处理新指令的边界。
Tab · 执行中把文本或可排队命令加入下一轮，显示 Queued follow-up。候选打开时先补全。Shift+Left 编辑最后一条未消费输入；停止或重启不自动重放。
Shift+Enter / Ctrl+J插入换行。长粘贴原子插入，折叠载荷仍保留原文。IME 候选确认、粘贴内换行与 Tab 不发送任务，也不批准工具。
@ 文件 / ! 命令@ 搜索并插入文件引用。! 发起用户 shell 命令，结果可供后续模型使用。! 与模型工具使用同一有效沙箱和审批策略。执行中可排队，不与当前写入工具竞争。
Up / Down、Ctrl+R召回或检索提示历史。选择后填入草稿，用户主动发送。多行文本先移动光标；取消搜索恢复原草稿。文件引用重新校验。
Ctrl+G使用配置的外部编辑器编辑草稿。返回后恢复输入和终端状态。不自动发送。编辑器失败保留可恢复内容。
Ctrl+T / Ctrl+OCtrl+T 打开详细转录；Ctrl+O 复制最近一条已完成回答。不把 Kimi 的 Ctrl+O 展开含义套到 Codex 键位上。剪贴板不可用时明确提示。
Esc面板中返回；审批中取消该审批交互；输入区中中断当前轮次。空输入区连按两次进入上一条提示编辑。编辑旧提示后产生新的会话分支，不回滚已写入文件。普通面板的 Esc 不停止当前工具。
Ctrl+C / Ctrl+DCtrl+C 优先交给当前面板；主界面活跃时中断，空闲时退出。Ctrl+D 在空输入且无面板时退出，其余由编辑器处理。以本次固定 Codex 提交为准，双按退出实验已关闭。退出先请求清理，不靠清空 PID 锁冒充停止。
? / Ctrl+L空输入的 ? 显示快捷键；Ctrl+L 清理当前终端视图，保留会话。/clear 是新会话，含义不同。未知 slash 提示未知命令，已后置命令提示不支持，草稿保留。

在线文档和本地源码可能位于不同发布阶段。核心输入行为以官方 CLI reference 为基准；审批、键位冲突与退出细节以固定提交源码校准。发版前针对目标 Codex 版本做一次差异核对，不追逐每个实验功能。

功能使用 Codex 名称，不另建词汇

下面是首版范围。保留同名操作的含义；已后置的功能不显示为可用，也不占用同名命令做另一件事。迁移兼容是产品主线，Goal、多代理与复杂插件仍可继续后置。

功能与入口首版规格运行中
/model选择已配置模型及支持的推理等级。显示当前值，下一次模型请求采用已生效配置。可打开，后续请求生效
/permissions、/status选择标准权限预设；状态显示实际 sandbox、approval policy、目录、模型和用量。可用，进行中动作不热改
/new、/clear同目录新会话；/clear 还清理终端视图。原会话与文件保留。完成或中断后执行
/resume、/rename检索恢复历史、修改名称。恢复只读历史与当前工作区，不重跑旧命令。可打开；切换前中断并清理
/fork、双 Esc 编辑从当前或被编辑提示的位置创建分支。Pi SessionManager 管消息树。派生前收敛当前动作
/compact调用 SDK 压缩有效上下文，原始会话历史继续保留。只在空闲执行
/diff默认 Git 工作目录差异，涵盖 staged、unstaged、untracked。单列 unified diff。可用，标明仍在变化
/review模型审查入口，选择未提交改动、分支比较或指定提交。结果以可定位问题呈现，不自动修复。当前轮结束后启动
/mention、@明确文件上下文。提交时校验路径、读取范围、模型能力与大小。可编辑或随输入提交
/copy、Ctrl+O复制最近完整回答；没有完整回答时显示不可用。可用，不复制未完成流
/init生成 AGENTS.md 草稿，遵守有效权限，已有文件不静默覆盖。只在空闲执行
/ps、/stop查看受管 shell 列表与输出；/stop 停止这些命令，不改名为“取消模型轮次”。可用，Esc 另负责中断轮次
/statusline、/theme尾部信息排列和代码主题设置。模型、推理等级、目录、权限、分支、上下文用量保持可见；窄屏换行。本地展示设置可用
/quit、/exit同义退出入口。收敛执行、保存可保存记录，恢复终端。发起停止并退出

删除上一版自定义主入口。 /changes 改为 /diff，/sessions 改为 /resume；/stop 恢复为受管终端停止。额外的验证证据、运行基线和输出工件仍保存，但放入详细转录与 diff 辅助信息，不要求 Codex 用户学习 /checks 或 /context 才能完成工作。

迁移与明确后置

按同名目录信任、AGENTS.md 指令和模型配置习惯设计。后续提供预览式 Codex 配置导入；首版不声称无损导入 Codex rollout 或共享其会话格式。

暂不发布 /goal、/agent、/mcp、/plugins、/memories、持久 Plan 与云入口。媒体输入、非交互 exec 和长期规则可按需求补齐。输入这些已知命令时显示 Not available in this release，不让模型把它当普通任务执行。

完整操作闭环保持简洁

情形界面与动作必须成立的结果
首次启动目录信任、模型配置、权限摘要，然后直接进入输入区。已信任项目默认 Auto 语义；未信任目录先 Read Only。取消不留下伪装成功的配置。
日常修改与测试Enter 发起；工具紧凑展示。工作区内普通命令自动运行，越界才审批。已有用户修改保留。最终回答说清修改、验证范围和未完成事项。
新增要求Enter 进入当前轮；Tab 等当前轮完成后再处理。队列显示顺序，可编辑。接收、消费与取消各有身份。恢复不自动发送旧草稿或队列。
审批 / 主动提问尾部选择面板接管焦点。审批说明额外权限；需求提问说明选择内容。两类面板不混淆，Full Access 也可以询问需求。取消不默认选择第一个选项。
查看改动 / 审查/diff 看实际文件；/review 请求模型找问题；Ctrl+T 看命令详情。/diff 的默认范围与 Codex 相同。测试成功来自实际 exit，模型自述不能制造证据。
失败与中断显示 Failed、Interrupted 或 Stopping。保留草稿和现存文件。不自动回滚；停止撤销旧审批。只有受管进程树确认退出后才能开始冲突写入。
恢复与占用/resume 预览目录、时间和结果。另一宿主持有工作区时显示 Read-only viewer。一个真实目录只有一个 writer。旧执行未知时显示 Execution unconfirmed，不能因恢复消息就解锁。
连接 / 存储错误显示错误原因与重试入口，如 Authentication failed、History not saved。不泄露密钥；不自动重跑有副作用的命令；记录未确认时阻止继续写入。

会话选择器取消恢复原草稿。损坏记录显示可解析内容与错误，不静默新建空会话。首次打开 diff 默认工作目录全量，运行前基线仅作为可选辅助比较，不替换用户对 /diff 的理解。

让兼容落到执行层，而不只换文案

SDK 与会话所有权保持不变。为 Codex 的输入和权限契约增加两个必要模块：输入交付记录与沙箱执行器。取消上一版“整轮配置完全冻结”的硬限制，改为在模型请求和工具启动时捕获动作快照。

边界落地方式
输入交付一个 inputId 对应 draft、accepted、consumed、cancelled。Enter 接到 SDK steer，Tab 接到 followUp。消费前的输入可编辑；停止同时清理 SDK 队列和宿主交付记录，未消费内容返回未发送状态。
权限域PermissionPreset 独立于 sandbox、approval policy 与 session grants。每次工具启动捕获有效策略与参数摘要。模式切换不能改变已执行中的授权，也不能借用旧审批。
沙箱执行统一 SandboxExecutor 接口，优先复用成熟的、许可允许的隔离实现。Windows 先验证现成 Codex sandbox 后端作为开发适配路径；发布时锁定并打包可维护执行后端，不假定用户机器装有 Codex。按平台探测能力，失败不无隔离回退。
文件与 shell文件工具在真实边界内检查路径和受保护元数据；shell 由 OS 隔离落实。一次额外授权放行具体动作，常规项目命令不走泛化危险关键词审批。Full Access 则显式使用无沙箱执行策略。
会话与配置Pi SessionManager 继续拥有历史、分支和模型变化。ArkCode 只保存草稿、输入交付、授权与工件。使用公共 setModel；选中模型不等于替换已经在流式返回的旧请求。
停止与事实撤销审批、清理未消费输入、SDK abort、确认受管命令退出。agent_settled 表示 SDK 自动续跑收敛；worker 退出不是子进程树退出，message_end 不是存储确认。

首版交付顺序

  1. 先兑现权限。 已信任目录自动运行工作区测试；网络与越界写入触发审批。Read Only 不能被 shell 绕过。Full Access 的明确确认与实际执行一致。
  2. 再兑现迁移习惯。 Enter steer、Tab follow-up、! shell、Codex 命令与键位，接着是恢复、fork、diff 和 review。每个入口都使用真实事件与输出。
  3. 最后收紧发布质量。 中文 IME、粘贴、raw mode 恢复、输出控制序列过滤、权限失效、崩溃清理与存储故障。原生终端才是产品验收对象。

与上一版相比，队列、fork、轻量 review 和真实沙箱被提前，因为它们直接影响 Codex 用户的核心习惯。Goal、多代理与持久 Plan 继续后置。网页只说明设计，不承担原生产品的状态机演示。
