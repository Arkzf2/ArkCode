# 会话、运行与历史

[English](../../en/concepts/session-lifecycle.md) | 简体中文 | [文档首页](../README.md)

会话保存一段可继续的对话。一次提交或继续处理队列会产生 agent run，其中可能多次请求模型并执行工具。同一个终端宿主可以持有多个独立会话，当前视图只决定输入和展示路由。

## 并发和所有权

不同会话可以同时在同一工作区运行。每个会话只有一个宿主拥有输入和持久化写入权，其他宿主成为 viewer。这个约束防止两个进程同时改写同一会话历史，不协调不同会话对工作区文件的修改。

fork 创建新的会话历史分支，不创建文件快照或 Git worktree。原会话继续存在，工作区文件由所有使用它的程序共享。

## shell 句柄

bash 交回一个仍在运行的命令时，session_id 标识当前 agent run 内的持续进程。它不是对话会话 ID。多个工具调用或 CodeMode 脚本可以继续观察同一进程，整个 run 结束时会清理句柄和进程。

工具 wait 到期只结束本次观察，不等于取消进程。退出终端、中断任务和 stop 会请求清理。只有确认的终态才说明受管进程清理已经完成；外部 MCP 效果另由服务决定。

## 保存和恢复

`sessions/` 保存 JSONL 历史，`runs/` 保存运行标记。历史恢复读取对话和检查点，不重新执行工具。活动运行标记尚未得到结束确认时，恢复会显示 Execution unconfirmed，并限制执行。

中断不会回滚文件。历史记录说明过去发生过什么，不能替代对磁盘、进程和外部服务当前状态的检查。用户操作见[会话管理](../guides/sessions.md)，异常情况见[故障排查](../troubleshooting.md)。
