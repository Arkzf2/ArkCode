# 模型上下文与压缩

[English](../../en/concepts/context-and-compaction.md) | 简体中文 | [文档首页](../README.md)

模型上下文包含当前系统规则、有效工具声明、用户任务和当前会话的有效历史。ArkCode 在请求准备时更新环境、项目指令、Skills 目录和工具可用性。终端显示的完整转录不一定全部出现在下一次模型请求中。

## 项目资源如何进入上下文

AGENTS.md 按信任、目录范围和字节预算加载。Skills 普通目录只提供名称、描述和路径，正文由明确选择或 read 加载。文件提及与用户明确输入一起处理，加载产生的内容不会替代原始用户输入的来源记录。

动态环境变化在后续请求生效，包括同一轮工具执行后的请求。已经发出的请求不能撤回修改。权限和工具可用性仍在实际执行边界检查，历史提示不授予权限。

## 何时压缩

`/compact` 手动触发，自动压缩则在完整工具批次闭合、下一次模型请求前检查输入预算。实际溢出也可以触发一次压缩后重试。触发、摘要策略和检查点由 ArkCode 管理，Pi 提供模型调用与历史基础能力。

设上下文窗口为 W，自动压缩触发阈值为 `floor(0.9 * W)`，与 Codex 默认机制一致。可用上下文上限为 `floor(0.95 * W)`。两者都不扣除 `maxTokens`，也不再按窗口大小固定预留 25k 或 50k。

`maxTokens` 限制输出，实际摘要输出上限还会按剩余上下文空间和压缩目标收缩。例如窗口为 256000 时，自动压缩触发点为 230400，可用上下文上限为 243200。预算为估算，不是供应商计费 token 的保证。底栏统计与累计费用也不是同一个指标。

## 压缩保留什么

ArkCode 生成任务摘要，保留最近最多 20000 token 预算的真实用户原文，并重建当前环境、规则和工具策略。保留预算不足时，用户文本可能按规则截短。精确摘要指令见[压缩提示参考](../reference/compaction-prompts.md)。

原始 JSONL 历史保留，TUI 恢复可以显示压缩前消息；这不代表模型仍能看到全部历史。历史加载过的 Skill 正文不会自动回填，排队且未交付的输入保留自己的正文快照。

摘要重试可能临时裁剪大型工具结果的中间文本，只作用于摘要输入副本，不修改原始日志。当前没有额外的历史检索工具或后台压缩服务。

## 成功与失败

新摘要、上下文基线和工具策略在同一检查点内提交。压缩成功后应用待生效的[工具模式](../reference/tool-modes.md)。提交前失败或取消保留旧策略；持久化或激活异常会阻止继续发送请求，直到恢复。

压缩失败而旧请求仍能容纳时会警告后继续，已经不能容纳时暂停。空摘要、输出截断和预算不满足不会被当作成功。模型可继续生成的短回答不会仅因为短而触发续写；明确 length 截断最多续写两次，仍失败时运行报错。
